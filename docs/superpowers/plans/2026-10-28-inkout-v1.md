# Inkout v1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the tested prototype into Inkout v1.0. That means new detectors, hide styles, site rules, tab-title hiding, per-tab counts and pause, presenter mode, and the Popup A, settings and welcome pages. It also covers the branding, store assets, README screenshots, a GitHub Pages site with the privacy policy, and a packaged zip ready for the Chrome Web Store.

**Architecture:** The content script keeps painting with the CSS Custom Highlight API, driven by settings in `chrome.storage.sync`. Per-tab state (counts, pause, sharing) lives in the service worker, persisted in `chrome.storage.session`. Pure state logic sits in small modules unit-tested in Node; the service worker only wires Chrome events to them. Everything in-page is proven by the headless-Chrome harness in `tests/browser/`.

**Tech Stack:** Chrome MV3, plain JavaScript (classic scripts, no build step), Node 22 `node:test`, the existing CDP harness, GitHub Actions and GitHub Pages.

**Spec:** [docs/superpowers/specs/2026-10-28-inkout-v1-design.md](../specs/2026-10-28-inkout-v1-design.md). Mockups: [docs/mockups/](../../mockups/README.md).

## Global Constraints

- No runtime or dev dependencies. Ask the user before adding any.
- No network requests from the extension, and no remote code. The website loads nothing from third parties.
- Downloading the Manrope font (Task 8) needs the user's explicit approval: state file name, source and size first.
- `npm test` passes before every commit (user's rule). Commits carry no AI attribution of any kind (user's rule).
- All work happens on branch `inkout-v1`, merged by one squash PR. `main` is protected: never push to it.
- Every new in-page behavior gets a test in `tests/browser/extension.test.js` with a pixel check (fixtures use red `#ff0000` text; `countRedPixels(...) === 0` means hidden).
- Popup ≤ 360×600 px with no scrollbars. Text contrast ≥ 4.5:1. Real `<button>`/`<input>` elements.
- Default hide style `blur`, default strength `medium`. Blur and Solid bar only.
- Support email: `kunaljmit036@gmail.com`. Site URL: `https://kunalkumarkkr01.github.io/inkout/`. Privacy policy URL: `https://kunalkumarkkr01.github.io/inkout/privacy.html`.
- Colors: ink `#0F1B2D`, teal `#0B7A75`, amber `#B45309`, red badge `#d93025`, blur grey `#3c4043`.
- Internal identifiers keep the `privacy-guard` prefix (CSS highlight names, data attributes, storage key `privacyGuardSettings`). Only user-visible text says Inkout.
- Chrome badges fit about 4 characters, so the paused badge is `❚❚` on amber. The tooltip says "Inkout is paused on this tab" (deviation from the spec's "PAUSED", flagged to the user).

## Review Focus

1. **A page that rewrites its title constantly** (Gmail's unread count): no flicker loop, and the raw title never shows. Test in Task 5: a fixture changes `document.title` every 50 ms for 1 s; every sample reads masked.
2. **A custom regex that is invalid or catastrophically slow** (`(a+)+$`): it must not freeze pages. Tests in Task 2 (`createCustomPattern` returns `null` for invalid input) and Task 9 (the settings page rejects a pattern that takes over 50 ms on 10,000 `a`s, with the error "This pattern is too slow to use").
3. **The service worker being stopped by Chrome** (MV3 workers sleep after about 30 s): pause and counts survive. Test in Task 6: stop the worker via CDP, then `getTabState` still reports the pause.
4. **Two tabs on the same site**: pausing one leaves the other protected. Test in Task 6.
5. **A manual switch during a share**: turning off manually during a share, then the share ending, stays off. Turning on manually, then the share ending with auto-off enabled, stays on. Test in Task 7.

### Task 2: New detectors

**Files:**
- Modify: `src/detectors.js`, `tests/detectors.test.js`

**Interfaces:**
- Produces `TYPES = ['email', 'apiKey', 'iban', 'card', 'phone', 'ip', 'custom']`. This is also the overlap priority: earlier wins.
- Produces `createCustomPattern(words: string[], { ignoreCase: boolean, asPatterns: boolean }) → RegExp | null`:
  - Literal mode escapes each word and wraps it in `(?<![\p{L}\p{N}])…(?![\p{L}\p{N}])`, with flags `gu` plus `i` when `ignoreCase`.
  - Pattern mode uses each word as a regex source.
  - Returns `null` for an empty list, or when any source fails to compile.
  - Patterns that can match an empty string are dropped.
- Changes `findMatches(text: string, customPattern: RegExp | null = null) → Array<{ type, start, end }>`.
- Patterns (exact):
  - `apiKey`, one alternation:
    - `(?:ghp|gho|ghu|ghs|ghr)_[A-Za-z0-9]{36}`
    - `github_pat_[A-Za-z0-9_]{82}`
    - `(?:AKIA|ASIA)[0-9A-Z]{16}`
    - `(?:sk|rk|pk)_(?:live|test)_[A-Za-z0-9]{16,}`
    - `xox[baprs]-[A-Za-z0-9-]{10,}`
    - `AIza[0-9A-Za-z_-]{35}`
    - `sk-(?:proj-|ant-)?[A-Za-z0-9_-]{20,}`
    - `eyJ[A-Za-z0-9_-]{8,}\.eyJ[A-Za-z0-9_-]{8,}\.[A-Za-z0-9_-]{8,}`

    Bounded by `(?<![A-Za-z0-9_-])` and `(?![A-Za-z0-9_-])`.
  - `iban`: `(?<![A-Z0-9])[A-Z]{2}\d{2}(?: ?[A-Z0-9]{4}){2,7}(?: ?[A-Z0-9]{1,4})?(?![A-Z0-9])`, accepted only if it has 15–34 alphanumerics with spaces removed and passes mod-97 (move the first 4 characters to the end, A=10…Z=35, remainder 1).
  - `ip`: IPv4 only, each octet 0–255, bounded by `(?<![\d.])` and `(?![\d.])`. IPv6 is out of scope.
